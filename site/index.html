Write to NTFS disks on your Mac

Windows-formatted USB drives, external SSDs and internal partitions, read-write. Unlatch runs libntfs-3g behind a small mount daemon on macFUSE, with a menu-bar app that mounts disks as you plug them in and a command-line tool, unlatch.

Install

Pick one. Unlatch builds are not signed with an Apple Developer ID and are not notarized (there is no paid Apple membership behind the project), so macOS asks once before opening the app.

One-time setup

The first time, Unlatch's setup window opens and checks each step; most of them it does for you. From a terminal, unlatch setup runs the same steps, and unlatch doctor checks them at any time.

  1. Open Unlatch It is not signed with an Apple Developer ID, so macOS asks first. In Applications, right-click Unlatch > Open > Open. If there is no Open button: System Settings > Privacy & Security > Open Anyway. Needed once per version. Do this before using unlatch in Terminal: until the app has been opened once, macOS stops its bundled programs without a message (zsh: killed).
  2. macFUSE In the setup window, click Install macFUSE. Unlatch downloads the latest release from macFUSE's GitHub page, checks it against the checksum macFUSE publishes, checks that the installer is signed by macFUSE's developer (Benjamin Fleischer, team 3T5GSNBU6W) and notarized by Apple, and then installs it. macOS asks for your password. If macFUSE is older than 5.4, the button says Update macFUSE. Homebrew users already have it. Prefer to do it yourself? Install it from macfuse.github.io or with brew install --cask macfuse; Unlatch then finds it.
  3. Allow macFUSE's kernel extension Apple Silicon Macs only load extensions from other developers after you allow it, once. Unlatch cannot do this for you:
    1. Shut down the Mac. Press and hold the power button until "Loading startup options" appears, then choose Options > Continue.
    2. In Recovery: Utilities > Startup Security Utility > select your startup disk > Security Policy > Reduced Security, and turn on "Allow user management of kernel extensions from identified developers". Click OK, enter your password, and restart.
    3. Back in macOS, run the setup window's self-test (or mount any disk). macOS reports a blocked system extension: open System Settings > Privacy & Security, click Allow next to "Benjamin Fleischer", and restart when asked.

    If you used macFUSE before, this is already done. Reduced Security only lets you approve extensions yourself; FileVault and other protections stay on.

  4. The helper, for real disks Disk images work without it. For USB drives and internal disks, click Install… in the setup window (or answer yes in unlatch setup); macOS asks for your password. Then click Allow in Full Disk Access: System Settings opens at Privacy & Security > Full Disk Access, and a Finder window shows Unlatch Helper. Drag it into the list and turn it on. Without it, macOS keeps the helper from opening removable disks.

    Why the helper and not the app? Disk devices can only be opened by root, so the small root helper opens them and hands them to Unlatch, which runs as you. macOS checks Full Disk Access for the program that opens the disk, which is the helper. In Login Items it appears under Unlatch.

  5. Self-test The setup window mounts a tiny built-in NTFS volume and reads it back. When it shows a green check, you are done. Optional: Open Unlatch at login, and Copy install command to put unlatch on your PATH (Homebrew does that already).

Check it all again any time from the menu bar: Setup & Health… opens the same window (its icon turns orange when something needs attention). From a terminal: unlatch doctor.

Use

  • Plug in a disk. Unlatch mounts NTFS disks in Finder, under /Volumes, read-write when Windows left them in a clean state. Settings choose which disks are mounted automatically, and the menu has per-disk choices.
  • Eject from the menu, from Finder, or with unlatch eject <disk> before unplugging.
  • Read-only when it is not safe to write. If Windows was hibernated, used Fast Startup, or did not finish writing, Unlatch mounts the disk read-only and says why. See Why is my disk read-only?
  • Command line: unlatch list, mount, unmount, eject, status, doctor; see the CLI reference.

What works

  • Reading and writing files and folders of any size, sparse and compressed files, Unicode names (stored in Windows' normal form, NFC).
  • Extended attributes, Finder tags and comments, kept as NTFS named streams, so no ._ files appear; Windows sees them as alternate data streams.
  • Symlinks: links within the disk are native Windows symlinks that Windows follows; other links use the WSL format. Windows symlinks and junctions are readable. Hard links.
  • Hidden files, and the Windows read-only attribute as a missing write permission.

Limitations

  • Windows Fast Startup keeps the disk "in use" when Windows only appears to shut down. Unlatch then mounts read-only. Turn Fast Startup off in Windows (Control Panel > Power Options > "Choose what the power buttons do"), or hold Shift while choosing Shut Down.
  • Windows name rules apply. Names cannot contain \ / : * ? " < > |, end with a dot or space, or be a reserved name such as CON or aux.txt; the Mac reports "invalid argument" for those.
  • Encrypted (EFS) files cannot be read or written; BitLocker volumes are not supported.
  • No journal replay. Like ntfs-3g, Unlatch does not replay the NTFS journal. Always eject before unplugging; if a disk was pulled out mid-write, run chkdsk on Windows before relying on it.
  • Not indexed by Spotlight, and not usable for Time Machine.
  • Permissions: files belong to the user who mounted the disk; NTFS access lists are not mapped.

Why is my disk read-only?

Unlatch writes to an NTFS disk only when Windows left it in a clean state. Otherwise writing could lose what Windows still has to write, or damage the disk, so Unlatch mounts it read-only and says why: in the menu (the badge next to the disk), in a notification, and in unlatch status <disk>. You can always read and copy files off the disk.

Unlatch never forces a write (ntfs-3g's recover or remove_hiberfile options are not used): only Windows can safely finish what Windows started. After fixing it, eject the disk on Windows and plug it into the Mac again, and Unlatch mounts it read-write. Or, if it is still connected: unlatch unmount <disk> then unlatch mount <disk>.

Performance

Speed depends on the disk. Numbers from the project's test Mac (Apple M2, 8 GiB, macOS 27.0.1); the method and raw results are in Bench/README.md.

Real drive: USB 2.0 stick

SanDisk Cruzer Blade 16 GB (USB 2.0), one 15.8 GB NTFS partition, Unlatch 1.0.0-beta.3, next to the stick's own speed (sudo dd on the raw partition) and Apple's exFAT driver on the same stick. Median of 3 runs, 512 MiB files.

Reads run at the stick's full speed; sequential writes reach 82% of it (exFAT 93%); small files and metadata are faster than exFAT, helped by the engine's write-back cache for NTFS's small metadata writes.

On a fast SSD image, sequential copies run at about 1.5–2.7 GB/s. The unlatch command

unlatch list [--json]                      # NTFS volumes and who has them mounted
unlatch mount <disk> [-r|--read-only] [--json]
unlatch unmount <disk> [--force]
unlatch unmount --all [--force]            # every volume Unlatch has mounted (before an update)
unlatch eject <disk> [--force]             # unmount, then eject the whole disk
unlatch status [<disk>] [--json]           # Unlatch's verdict per volume (clean, dirty, hibernated, ...)
unlatch doctor                             # check macOS, macFUSE, unlatch-fuse, the helper
unlatch setup [--yes] [--no-helper]        # install or update macFUSE, explain its approval, install the helper
sudo unlatch install-helper                # once, for real disks (not needed for disk images)
sudo unlatch uninstall-helper

<disk> is a BSD name (disk6s1), a device path (/dev/disk6s1 or /dev/rdisk6s1), a mount path (/Volumes/Seagate), or a volume label (case-insensitive; must name one volume).

mount mounts at /Volumes/<label>. It is read-write only when the volume is clean and nothing forces read-only. If Apple's read-only NTFS driver had the volume, Unlatch unmounts it first and gives it back if mounting fails.

list --json, status --json and mount --json print a stable JSON format ("schema": 1). For example:

unlatch status --json | jq -r '.volumes[] | select(.owner == "unlatch") | .mountPoint'

The full reference, including every JSON field: docs/cli.md.

Troubleshooting

Start with the menu bar's Setup & Health… window, or unlatch doctor in a terminal: it checks macOS, macFUSE and its system extension, unlatch-fuse, the helper, and the status directory, and says what to fix.

The disk does not mount, or Finder shows it read-only
  • Read-only with a reason: see Why is my disk read-only?
  • "macFUSE is not installed" / exit code 4: install it (brew install --cask macfuse), then allow its system extension: on Apple Silicon, Reduced Security in Recovery once, then System Settings > Privacy & Security > Allow. Restart if macOS asks.
  • "macOS blocked the Unlatch helper" (real disks only): give the helper Full Disk Access: System Settings > Privacy & Security > Full Disk Access > + > ⌘⇧G > /Library/PrivilegedHelperTools/Unlatch Helper.
  • "needs the helper": run Unlatch's setup again (menu > Finish setting up), or sudo unlatch install-helper.
  • Apple's read-only NTFS driver got the disk first: unlatch mount <disk> takes it over (and gives it back if mounting fails). Turning auto-mount on in Settings makes Unlatch claim NTFS disks as they appear.
  • The disk is not listed at all: diskutil list should show a Windows_NTFS or Microsoft Basic Data partition. BitLocker-encrypted partitions are not supported.
"Unlatch can't be opened because Apple cannot check it"

Unlatch is not signed with an Apple Developer ID. Right-click Unlatch in Applications > Open, then Open; or System Settings > Privacy & Security > Open Anyway.

unlatch in Terminal says "killed"

macOS stops the programs inside a downloaded, unsigned app until the app itself has been opened once. Open Unlatch from Applications with right-click > Open (or Open Anyway in Privacy & Security), then run unlatch again. Needed once per version.

Unmount or eject says the disk is busy

A program still has a file open on it. Close it, or find it with lsof +D /Volumes/<name>. Right after a large copy, macOS itself may hold the disk for a moment; Unlatch retries for a few seconds. unlatch unmount --force <disk> unmounts anyway, which can lose the open program's unsaved changes.

A folder shows up as empty, or a file name is missing
  • Names that break Windows' rules (a:b, CON, a trailing dot) cannot be created; programs get "invalid argument".
  • A damaged directory entry is skipped and logged instead of failing the whole folder. Run chkdsk X: /f on Windows.
Files named "Unlatch recovered N"

A rename was cut off by a crash or an unplug; Unlatch kept the file under this name the next time it mounted the disk. Check it and rename or delete it.

The disk was unplugged without ejecting

Plug it back in: Unlatch mounts it read-only if Windows' records say it was in use, and it repairs its own leftovers. To be sure the disk is consistent, run chkdsk X: /f on Windows. Always eject first next time.

It is slow

Unlatch keeps a write-back cache in memory and writes it out at least every second. Very slow USB 2 sticks and SMR hard disks are slow at small-file work under any file system.

Reporting a problem

  1. Settings > Troubleshooting > Export logs… saves the last hour of Unlatch's log.
  2. Note unlatch --version, macOS (sw_vers), macFUSE's version (unlatch doctor), and the disk (diskutil info <disk>; no personal data).
  3. Open an issue at github.com/Ramanan-Bala/unlatch/issues with what you did, what you expected and what happened. For anything that might be a security problem, see SECURITY.md instead.

Updating and uninstalling

Unlatch has no automatic updater: a signed updater needs an Apple Developer ID, which the project does not have. Once a day (Settings > Updates, on by default) the app asks GitHub for the list of releases, and the menu shows "Unlatch X is available…" when a newer version exists. Nothing about your Mac or disks is sent.

Update

brew upgrade --cask unlatch   # the app
brew upgrade unlatch          # the CLI formula

From the DMG: unlatch unmount --all, quit Unlatch, drag the new app over the old one and open it once with right-click > Open. Settings, auto-mount choices and the helper survive an update.

Upgrading from 1.0.0-beta.3 or earlier with Homebrew removes the helper once: open Setup & Health…, click Install… next to the helper, and allow it in Full Disk Access.

Uninstall

Settings > About > Uninstall Unlatch… unmounts the volumes, removes the helper and the login item, deletes Unlatch's settings and moves the app to the Trash. With Homebrew:

brew uninstall --cask --zap unlatch

macFUSE stays, since other software may use it; nothing on your NTFS disks belongs to Unlatch.

More: docs/updating.md, docs/uninstall.md.

Building from source

Xcode 27, XcodeGen, Git LFS, and macFUSE (for its headers):

Scripts/bootstrap.sh                # checks tools, builds libntfs-3g, generates Unlatch.xcodeproj
xcodebuild -scheme Unlatch build    # app, unlatch-fuse, helper, engine, test harness
swift build --package-path CLI      # the unlatch command
Scripts/release.sh --allow-dirty    # a local DMG in build/release/

How it is built

  • Engine/: a small C engine over libntfs-3g with one public header (unlatch_engine.h), a write-back page cache, and crash-leftover repair.
  • Fuse/: unlatch-fuse, the mount daemon, on libfuse's low-level API.
  • Helper/: a tiny privileged helper that only opens NTFS disk devices for the logged-in user and hands them to the daemon, which runs as you.
  • Shared/, CLI/, App/: Swift: disk detection and mounting, the unlatch command, the menu-bar app.

After 1.0

  • A native FSKit module, once the project can sign one (needs a paid Apple Developer membership), replacing macFUSE.
  • A repair assistant for disks that need chkdsk, and a format command (mkntfs).
  • Engine replacement behind unlatch_engine.h if a better NTFS implementation becomes available.
  • Localization.
