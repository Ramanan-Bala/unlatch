# Decisions

One line each: `D-NN: decision — reason — step`. Later steps depend on these; change one only with a new entry that supersedes it.

- D-01: License is GPL-3.0-or-later; contributions under DCO (`git commit -s`), no CLA — libntfs-3g is GPL-2.0-or-later and links in-process, so the whole is a GPL work — Step 01
- D-02: Platform is macOS 27+ on Apple Silicon (arm64 only, `ARCHS = arm64`) — macOS 27 brings the FSKit Handler protocols, KOIO and `FSClient.mountSingleVolume`, and has no Intel support — Step 01
- D-03: Names: product `Unlatch`, CLI `unlatch`, FS short name `unlatch`, engine prefix `ue_` — `ntfs` is Apple's name and collides; `ntfs_*` collides with libntfs-3g symbols — Step 01
- D-04: `BUNDLE_PREFIX` is `io.github.ramanan-bala` (app `…Unlatch`, extension `…Unlatch.FSModule`, App Group `group.…Unlatch`, log subsystem `…unlatch`) — matches the GitHub account `Ramanan-Bala` that hosts the public repo — Step 01
- D-05: `Unlatch.xcodeproj` is generated by XcodeGen from `project.yml` and not committed (it is in `.gitignore`); `Scripts/bootstrap.sh` regenerates it — one source of truth, no merge conflicts in `project.pbxproj` — Step 01
- D-06: Builds are ad-hoc signed for now, and the entitlements files (`App/Resources/Unlatch.entitlements`, `Extension/Resources/UnlatchFSModule.entitlements`) are kept in the repo but not referenced from `project.yml` — App Group and `com.apple.developer.fskit.fsmodule` need a provisioning profile, and ad-hoc builds fail with them; Step 08 must add a team and reference them before the extension can load — Step 01
- D-07: Swift packages use `swift-tools-version: 6.0` (Swift 6 mode, complete concurrency checking) with `platforms: [.macOS("27.0")]`; CLI depends on `swift-argument-parser` `from: "1.5.0"` (resolved 1.8.2, `CLI/Package.resolved` committed) — reproducible CLI builds — Step 01
- D-08: The FSKit extension target is an XcodeGen `extensionkit-extension` with `EXExtensionPointIdentifier = com.apple.fskit.fsmodule`; the app embeds it and the scheme `Unlatch` also builds `UnlatchEngine` and `unlatch-engine` — one `xcodebuild -scheme Unlatch build` covers every Xcode target — Step 01
