# Decisions

One line each: `D-NN: decision — reason — step`. Later steps depend on these; change one only with a new entry that supersedes it.

- D-01: License is GPL-3.0-or-later; contributions under DCO (`git commit -s`), no CLA — libntfs-3g is GPL-2.0-or-later and links in-process, so the whole is a GPL work — Step 01
- D-02: Platform is macOS 27+ on Apple Silicon (arm64 only, `ARCHS = arm64`) — macOS 27 brings the FSKit Handler protocols, KOIO and `FSClient.mountSingleVolume`, and has no Intel support — Step 01
- D-03: Names: product `Unlatch`, CLI `unlatch`, FS short name `unlatch`, engine prefix `ue_` — `ntfs` is Apple's name and collides; `ntfs_*` collides with libntfs-3g symbols — Step 01
- D-04: `BUNDLE_PREFIX` is `io.github.ramanan-bala` (app `…Unlatch`, extension `…Unlatch.FSModule`, App Group `group.…Unlatch`, log subsystem `…unlatch`) — matches the GitHub account `Ramanan-Bala` that hosts the public repo — Step 01
- D-05: `Unlatch.xcodeproj` is generated by XcodeGen from `project.yml` and not committed (it is in `.gitignore`); `Scripts/bootstrap.sh` regenerates it — one source of truth, no merge conflicts in `project.pbxproj` — Step 01
- D-06: Builds are ad-hoc signed for now, and the entitlements files (`App/Resources/Unlatch.entitlements`, `Extension/Resources/UnlatchFSModule.entitlements`) are kept in the repo but not referenced from `project.yml` — App Group and `com.apple.developer.fskit.fsmodule` need a provisioning profile, and ad-hoc builds fail with them; Step 08 must add a team and reference them before the extension can load — Step 01
- D-07: Swift packages use `swift-tools-version: 6.0` (Swift 6 mode, complete concurrency checking) with `platforms: [.macOS("27.0")]`; CLI depends on `swift-argument-parser` `from: "1.5.0"` (resolved 1.8.2, `CLI/Package.resolved` committed) — reproducible CLI builds — Step 01
- D-08: The FSKit extension target is an XcodeGen `extensionkit-extension` with `EXExtensionPointIdentifier = com.apple.fskit.fsmodule`; the app embeds it and the scheme `Unlatch` also builds `UnlatchEngine` and `unlatch-engine` — one `xcodebuild -scheme Unlatch build` covers every Xcode target — Step 01
- D-09: libntfs-3g is pinned to release 2026.9.28 (latest stable; the plan expected 2022.10.3). It is vendored as the release tarball from tuxera.com (SHA-256 `350d9415…f295c8`, matching the release notes), extracted into `Engine/vendor/ntfs-3g/`, and recorded in `Engine/vendor/VERSION` — the tarball ships a generated `configure`, so no autotools are needed, and it fixes several CVEs found since 2022 — Step 02
- D-10: libntfs-3g is configured with `--disable-ntfs-3g --disable-mount-helper --enable-ntfsprogs --disable-crypto --disable-plugins --disable-nfconv --disable-shared --enable-static`, plus `--exec-prefix` so nothing installs to `/bin` or `/lib`. `--disable-nfconv` means the library does no NFC/NFD conversion itself, so the host normalizes names to NFC (B4). `--disable-plugins` means no `dlopen` of reparse plugins in the extension — Step 02
- D-11: `libntfs-3g.a` is merged into `libUnlatchEngine.a` (`OTHER_LIBTOOLFLAGS`), so the extension and `unlatch-engine` link the one engine archive. The ntfs-3g include path is set on the `UnlatchEngine` target only — Step 02
- D-12: `Scripts/build-ntfs3g.sh` builds out of tree, from a copy in `build/ntfs3g-src` with `Engine/vendor/patches/*.patch` applied, so the vendored tree is never modified. `Scripts/bootstrap.sh` runs it when `build/ntfs3g/lib/libntfs-3g.a` is missing, and the `UnlatchEngine` pre-build phase fails with a clear message if the library is absent — Step 02
- D-13: Engine sources compile against libntfs-3g's own `config.h` (copied by `build-ntfs3g.sh` to `build/ntfs3g/config/`, with `HAVE_CONFIG_H=1`), and the ntfs-3g headers come in through `-isystem build/ntfs3g/include` — the headers change struct layouts on `HAVE_*` macros, so they must match how the library was built; `-isystem` keeps upstream `-Wdocumentation` warnings out of our `-Werror` build — Step 03
- D-14: Open question 3 is answered: the custom `ntfs_device_operations` path works fully with `ntfs_device_mount` plus `ntfs_create_lru_caches`, with no patches. One workaround: `ntfs_volume_startup` retries read-only whenever the device's `open` returns `EROFS`, even without `NTFS_MNT_MAY_RDONLY`. So `ue_open` rejects a read-write request on a non-writable `ue_io_t` up front, and treats a volume that comes back `NVolReadOnly` as `EROFS`. The `seek` bridge must fail past `size_bytes`, because `bootsect.c` detects truncated volumes that way — Step 03
- D-15: `ue_probe` returns 0 with a verdict for every readable device (NOT_NTFS and CORRUPT included). It returns an errno only for bad arguments or ENOMEM. Severity order: HIBERNATED (active `hiberfil.sys`, or a `$LogFile` restart page 2.0 from Fast Startup or an abrupt unplug) > CORRUPT > UNCLEAN_LOG > DIRTY > CLEAN. A mount that fails behind a valid NTFS boot sector is CORRUPT (truncated, damaged MFT), not NOT_NTFS. `ue_open` never degrades to read-only: a read-write open fails with EPERM, EOPNOTSUPP or EROFS. The logfile check re-implements libntfs-3g's static `ntfs_volume_check_logfile` on top of the exported `ntfs_check_logfile` and `ntfs_is_logfile_clean` — Step 03
- D-16: The libntfs-3g log handler stays at its default (`ntfs_log_handler_null`), so the engine is silent. Routing it to OSLog category `engine` is left for the extension (Step 08) — Step 03
- D-17: The engine C tests live in `Tests/Engine/`. `Scripts/test-engine.sh` builds them with clang against the Xcode-built `libUnlatchEngine.a` (in `build/DerivedData`), makes fixture images in `build/test-engine/` with ntfsprogs plus `Tests/Engine/set_dirty.c` (a direct byte patch of `$Volume` in both `$MFT` and `$MFTMirr`), and runs the harness checks, `leaks --atExit` and a grep for the include boundary. `EngineTool/file_io.c` is the shared file-backed `ue_io_t` — Step 03
- D-18: Inode lifetime: the engine keeps one `ntfs_inode` per MFT record in a hash cache (`Engine/src/icache.c`), so a record is never open twice. `get_inode` opens on first use and checks the 16-bit sequence number; a mismatch or a freed record returns ESTALE. Sequence 0 is accepted only for `UE_ROOT_INO`. The root stays cached until `ue_close`, `ue_release` drops any other entry, and `ue_close` closes them all. `ue_readdir` reads each child's attributes with a temporary open and does not cache children — Step 04
- D-19: Case: the volume runs in libntfs-3g ignore-case mode (`ntfs_set_ignore_case`), so lookups are case-insensitive through `$UpCase`. But `ntfs_filldir` lowercases names in that mode, so `ue_readdir` sets `NVolSetCaseSensitive` around `ntfs_readdir` and clears it afterwards; names come back case-preserved — Step 04
- D-20: Test fixtures are built with libntfs-3g directly by `Engine/src/fixtures/mkfixture.c`, which reads a small script language: mkdir, file, sparse, uninit, many, flags, plus `gen`. It lives under `Engine/src` because of the include boundary, is excluded from the `UnlatchEngine` target, and is built by `Scripts/test-engine.sh`. `Engine/src/fixtures/gen.h` is the deterministic content stream shared with the tests — Step 04
- D-21: Patch `0001-ntfs_readdir-fix-bitmap-offset-on-resume.patch`: upstream `ntfs_readdir` starts its index-bitmap bit cursor at 0 instead of `bmp_pos & 7` when resuming. That misaligns every in-use test, which skips blocks or reads past `$INDEX_ALLOCATION` (EIO). The patch also stops at the end of `$INDEX_ALLOCATION`. Worth sending upstream — Step 04
- D-22: Names convert UTF-8 ↔ UTF-16 with libntfs-3g's built-in converter (`ntfs_mbstoucs`/`ntfs_ucstombs`; `use_utf8` defaults to 1, so there is no locale dependence). The engine does not normalize: NFD input misses an NFC name, and NFC normalization is the host's job (B4) — Step 04
- D-23: Attribute conventions:
  - `mode` is fixed at 0755 for dirs and 0644 for files (DOS read-only is reported as `UE_F_READONLY`; the host maps it to `UF_IMMUTABLE`).
  - Directory size is the `$I30` `$INDEX_ALLOCATION` data size, or 0.
  - `nlink` counts `$FILE_NAME` attributes except DOS 8.3 ones.
  - `alloc_size` is `compressed_size` for sparse or compressed data.
  - The readdir cookie is libntfs-3g's position plus 1, and the verifier is the directory's `last_data_change_time`.
  - `emit` returning false means the entry was not taken.
  - `ue_get_stats` exposes debug counters (`inode_opens`, `cached_inodes`).
  - `ue_statfs` counts free clusters once at open and relies on libntfs-3g to keep the count current — Step 04
- D-24: **Supersedes D-18.** The engine keeps no `ntfs_inode` open between calls. Every call opens what it needs (`ue_iget` checks the sequence number; a freed or reused record gives ESTALE) and closes it before returning, as lowntfs-3g does. libntfs-3g's closed-inode cache (`CACHE_NIDATA`, synced on close) keeps re-opens cheap. Holding inodes open across calls is unsafe because libntfs-3g opens parent directories by reference internally (for example to sync a file name into its parent's index), which would create a second, diverging in-memory copy of a record. `ue_readdir` keeps the directory open for one call and reads children read-only outside `ntfs_readdir` — Step 05
- D-25: Unlink of a held file: the engine tracks the items the host holds (from `ue_lookup`/`ue_create` until `ue_release`; `Engine/src/held.c`). When a file's last name is removed while held, the name is replaced by a hidden ghost name, `.unlatch-ghost-N` **in the root directory** (changed from "same directory" in Step 06, see D-30), flagged HIDDEN and SYSTEM. The ghost is deleted on `ue_release`, or at `ue_close` for any still left. This is lowntfs-3g's ghost scheme, keyed to FSKit's reclaim instead of FUSE release. Names starting `.unlatch-ghost-` or `.unlatch-rename-` are hidden from lookup and readdir, and cannot be created. A crash can leave ghosts behind (Step 17) — Step 05
- D-26: Rename uses only link and unlink steps, in lowntfs-3g's order, so every intermediate state is a valid volume:
  - Plain move: link the new name, then unlink the old.
  - Replace: park the target as `.unlatch-rename-N`, unlink its name, link the source, unlink the source's old name, then remove the parked target (a ghost if held).
  - Case-only rename: link a temp name, unlink the old, link the new, unlink the temp. `$I30` collates case-insensitively, so `A` can't be linked next to `a`.
  - Same item under another name in another directory: a no-op (POSIX).
  - A directory may not move into its own subtree (EINVAL); this is checked by walking `$FILE_NAME` parents. Type rules: ENOTDIR, EISDIR, ENOTEMPTY; EXCL → EEXIST. Each failed step is rolled back.
  - Not crash-atomic: a crash can leave a temp name or both names (Step 17) — Step 05
- D-27: New names (create, rename target) follow Win32 rules via `ntfs_forbidden_names(vol, …, strict=TRUE)`: no `\ / : * ? " < > |` or control characters, no trailing dot or space, no CON/PRN/AUX/NUL/COM1-9/LPT1-9 with or without an extension. These fail with EINVAL; more than 255 UTF-16 units gives ENAMETOOLONG. Existing names are found case-insensitively (EEXIST). libntfs-3g creates POSIX-namespace names — Step 05
- D-28: Write-path semantics:
  - `ue_write` updates mtime and ctime and sets ARCHIVE. It returns EACCES on encrypted files and EOPNOTSUPP on reparse points (symlinks, junctions, cloud placeholders) until Step 16. A short write returns 0 with `*done` short; a failed first write returns the errno (ENOSPC).
  - `ue_create`: mode without the owner-write bit sets DOS READONLY; it updates the parent's mtime and ctime, which `ntfs_create` doesn't.
  - `ue_setattr`: size uses `ntfs_attr_truncate` (growing makes a hole); compressed files grow by writing a final zero. Times are taken exactly (100 ns resolution), and ctime becomes now unless given. Only HIDDEN, SYSTEM, READONLY and ARCHIVE can be changed. A file's mode only affects READONLY, and `ue_getattr` reports 0444 for read-only files (refines D-23).
  - `ue_sync` flushes the device; libntfs-3g syncs inodes on close.
  - Every mutating call on a read-only engine returns EROFS — Step 05
- D-29: The randomized model test is `unlatch-engine fsx` (`EngineTool/fsx.c`), run on an empty 512 MB image. The model predicts exact errnos and is compared every op; limits are 96 nodes and 2 MiB per file. `Scripts/fsx-soak.sh` runs seeds in parallel on APFS clones. Failing seeds go to `Tests/fsx-regressions.txt`, which `Scripts/test-engine.sh` re-runs and CI will too — Step 06
- D-30: Ghosts (D-25) live in the root directory. fsx found that a ghost left in its parent made `rmdir` of an apparently empty directory fail with ENOTEMPTY. POSIX allows removing a directory whose only content is an open, unlinked file. Root placement also means crash leftovers sit in one known directory (Step 17 sweep) — Step 06
- D-31: The Windows oracle is `Scripts/chkdsk-vm.sh`. It wraps an image as a fixed VHD (`Tests/oracle/mkvhd.c`: an MBR with an NTFS partition at LBA 2048, hidden sectors patched to 2048, VHD footer), attaches it read-only with `Mount-DiskImage`, runs `chkdsk X:` with no `/f`, and stores the report with the image SHA-256 in `Tests/oracle/`. It is automated over SSH (`WINDOWS_SSH=user@host`, a Windows 11 Arm VM in UTM or Parallels with OpenSSH Server); otherwise it prints the manual steps (`docs/testing.md`) — Step 06
