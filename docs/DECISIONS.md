- D-09: libntfs-3g is pinned to release 2026.9.28 (latest stable; the plan expected 2022.10.3). It is vendored as the release tarball from tuxera.com (SHA-256 `350d9415…f295c8`, matching the release notes), extracted into `Engine/vendor/ntfs-3g/`, and recorded in `Engine/vendor/VERSION` — the tarball ships a generated `configure`, so no autotools are needed, and it fixes several CVEs found since 2022 — Step 02

- D-11: `libntfs-3g.a` is merged into `libUnlatchEngine.a` (`OTHER_LIBTOOLFLAGS`), so the extension and `unlatch-engine` link the one engine archive. The ntfs-3g include path is set on the `UnlatchEngine` target only — Step 02
- D-12: `Scripts/build-ntfs3g.sh` builds out of tree, from a copy in `build/ntfs3g-src` with `Engine/vendor/patches/*.patch` applied, so the vendored tree is never modified. `Scripts/bootstrap.sh` runs it when `build/ntfs3g/lib/libntfs-3g.a` is missing, and the `UnlatchEngine` pre-build phase fails with a clear message if the library is absent — Step 02
- D-13: Engine sources compile against libntfs-3g's own `config.h` (copied by `build-ntfs3g.sh` to `build/ntfs3g/config/`, with `HAVE_CONFIG_H=1`), and the ntfs-3g headers come in through `-isystem build/ntfs3g/include` — the headers change struct layouts on `HAVE_*` macros, so they must match how the library was built; `-isystem` keeps upstream `-Wdocumentation` warnings out of our `-Werror` build — Step 03
- D-14: Open question 3 is answered: the custom `ntfs_device_operations` path works fully with `ntfs_device_mount` plus `ntfs_create_lru_caches`, with no patches. One workaround: `ntfs_volume_startup` retries read-only whenever the device's `open` returns `EROFS`, even without `NTFS_MNT_MAY_RDONLY`. So `ue_open` rejects a read-write request on a non-writable `ue_io_t` up front, and treats a volume that comes back `NVolReadOnly` as `EROFS`. The `seek` bridge must fail past `size_bytes`, because `bootsect.c` detects truncated volumes that way — Step 03
- D-15: `ue_probe` returns 0 with a verdict for every readable device (NOT_NTFS and CORRUPT included). It returns an errno only for bad arguments or ENOMEM. Severity order: HIBERNATED (active `hiberfil.sys`, or a `$LogFile` restart page 2.0 from Fast Startup or an abrupt unplug) > CORRUPT > UNCLEAN_LOG > DIRTY > CLEAN. A mount that fails behind a valid NTFS boot sector is CORRUPT (truncated, damaged MFT), not NOT_NTFS. `ue_open` never degrades to read-only: a read-write open fails with EPERM, EOPNOTSUPP or EROFS. The logfile check re-implements libntfs-3g's static `ntfs_volume_check_logfile` on top of the exported `ntfs_check_logfile` and `ntfs_is_logfile_clean` — Step 03
- D-16: The libntfs-3g log handler stays at its default (`ntfs_log_handler_null`), so the engine is silent. Routing it to OSLog category `engine` is left for the extension (Step 08) — Step 03
- D-17: The engine C tests live in `Tests/Engine/`. `Scripts/test-engine.sh` builds them with clang against the Xcode-built `libUnlatchEngine.a` (in `build/DerivedData`), makes fixture images in `build/test-engine/` with ntfsprogs plus `Tests/Engine/set_dirty.c` (a direct byte patch of `$Volume` in both `$MFT` and `$MFTMirr`), and runs the harness checks, `leaks --atExit` and a grep for the include boundary. `EngineTool/file_io.c` is the shared file-backed `ue_io_t` — Step 03
- D-18: Inode lifetime: the engine keeps one `ntfs_inode` per MFT record in a hash cache (`Engine/src/icache.c`), so a record is never open twice. `get_inode` opens on first use and checks the 16-bit sequence number; a mismatch or a freed record returns ESTALE. Sequence 0 is accepted only for `UE_ROOT_INO`. The root stays cached until `ue_close`, `ue_release` drops any other entry, and `ue_close` closes them all. `ue_readdir` reads each child's attributes with a temporary open and does not cache children — Step 04
- D-19: Case: the volume runs in libntfs-3g ignore-case mode (`ntfs_set_ignore_case`), so lookups are case-insensitive through `$UpCase`. But `ntfs_filldir` lowercases names in that mode, so `ue_readdir` sets `NVolSetCaseSensitive` around `ntfs_readdir` and clears it afterwards; names come back case-preserved — Step 04
- D-20: Test fixtures are built with libntfs-3g directly by `Engine/src/fixtures/mkfixture.c`, which reads a small script language: mkdir, file, sparse, uninit, many, flags, plus `gen`. It lives under `Engine/src` because of the include boundary, is excluded from the `UnlatchEngine` target, and is built by `Scripts/test-engine.sh`. `Engine/src/fixtures/gen.h` is the deterministic content stream shared with the tests — Step 04
- D-21: Patch `0001-ntfs_readdir-fix-bitmap-offset-on-resume.patch`: upstream `ntfs_readdir` starts its index-bitmap bit cursor at 0 instead of `bmp_pos & 7` when resuming. That misaligns every in-use test, which skips blocks or reads past `$INDEX_ALLOCATION` (EIO). The patch also stops at the end of `$INDEX_ALLOCATION`. Worth sending upstream — Step 04
- D-22: Names convert UTF-8 ↔ UTF-16 with libntfs-3g's built-in converter (`ntfs_mbstoucs`/`ntfs_ucstombs`; `use_utf8` defaults to 1, so there is no locale dependence). The engine does not normalize: NFD input misses an NFC name, and NFC normalization is the host's job (B4) — Step 04
- D-23: Attribute conventions:
  - `mode` is fixed at 0755 for dirs and 0644 for files (DOS read-only is reported as `UE_F_READONLY`; the host maps it to `UF_IMMUTABLE`).
  - Directory size is the `$I30` `$INDEX_ALLOCATION` data size, or 0.
  - `nlink` counts `$FILE_NAME` attributes except DOS 8.3 ones.
  - `alloc_size` is `compressed_size` for sparse or compressed data.
  - The readdir cookie is libntfs-3g's position plus 1, and the verifier is the directory's `last_data_change_time`.
  - `emit` returning false means the entry was not taken.
  - `ue_get_stats` exposes debug counters (`inode_opens`, `cached_inodes`).
  - `ue_statfs` counts free clusters once at open and relies on libntfs-3g to keep the count current — Step 04
- D-24: **Supersedes D-18.** The engine keeps no `ntfs_inode` open between calls. Every call opens what it needs (`ue_iget` checks the sequence number; a freed or reused record gives ESTALE) and closes it before returning, as lowntfs-3g does. libntfs-3g's closed-inode cache (`CACHE_NIDATA`, synced on close) keeps re-opens cheap. Holding inodes open across calls is unsafe because libntfs-3g opens parent directories by reference internally (for example to sync a file name into its parent's index), which would create a second, diverging in-memory copy of a record. `ue_readdir` keeps the directory open for one call and reads children read-only outside `ntfs_readdir` — Step 05
- D-25: Unlink of a held file: the engine tracks the items the host holds (from `ue_lookup`/`ue_create` until `ue_release`; `Engine/src/held.c`). When a file's last name is removed while held, the name is replaced by a hidden ghost name, `.unlatch-ghost-N` **in the root directory** (changed from "same directory" in Step 06, see D-30), flagged HIDDEN and SYSTEM. The ghost is deleted on `ue_release`, or at `ue_close` for any still left. This is lowntfs-3g's ghost scheme, keyed to FSKit's reclaim instead of FUSE release. Names starting `.unlatch-ghost-` or `.unlatch-rename-` are hidden from lookup and readdir, and cannot be created. A crash can leave ghosts behind (Step 17) — Step 05
- D-26: Rename uses only link and unlink steps, in lowntfs-3g's order, so every intermediate state is a valid volume:
  - Plain move: link the new name, then unlink the old.
  - Replace: park the target as `.unlatch-rename-N`, unlink its name, link the source, unlink the source's old name, then remove the parked target (a ghost if held).
  - Case-only rename: link a temp name, unlink the old, link the new, unlink the temp. `$I30` collates case-insensitively, so `A` can't be linked next to `a`.
  - Same item under another name in another directory: a no-op (POSIX).
  - A directory may not move into its own subtree (EINVAL); this is checked by walking `$FILE_NAME` parents. Type rules: ENOTDIR, EISDIR, ENOTEMPTY; EXCL → EEXIST. Each failed step is rolled back.
  - Not crash-atomic: a crash can leave a temp name or both names (Step 17) — Step 05
- D-27: New names (create, rename target) follow Win32 rules via `ntfs_forbidden_names(vol, …, strict=TRUE)`: no `\ / : * ? " < > |` or control characters, no trailing dot or space, no CON/PRN/AUX/NUL/COM1-9/LPT1-9 with or without an extension. These fail with EINVAL; more than 255 UTF-16 units gives ENAMETOOLONG. Existing names are found case-insensitively (EEXIST). libntfs-3g creates POSIX-namespace names — Step 05
- D-28: Write-path semantics:
  - `ue_write` updates mtime and ctime and sets ARCHIVE. It returns EACCES on encrypted files and EOPNOTSUPP on reparse points (symlinks, junctions, cloud placeholders) until Step 16. A short write returns 0 with `*done` short; a failed first write returns the errno (ENOSPC).
  - `ue_create`: mode without the owner-write bit sets DOS READONLY; it updates the parent's mtime and ctime, which `ntfs_create` doesn't.
  - `ue_setattr`: size uses `ntfs_attr_truncate` (growing makes a hole); compressed files grow by writing a final zero. Times are taken exactly (100 ns resolution), and ctime becomes now unless given. Only HIDDEN, SYSTEM, READONLY and ARCHIVE can be changed. A file's mode only affects READONLY, and `ue_getattr` reports 0444 for read-only files (refines D-23).
  - `ue_sync` flushes the device; libntfs-3g syncs inodes on close.
  - Every mutating call on a read-only engine returns EROFS — Step 05
- D-29: The randomized model test is `unlatch-engine fsx` (`EngineTool/fsx.c`), run on an empty 512 MB image. The model predicts exact errnos and is compared every op; limits are 96 nodes and 2 MiB per file. `Scripts/fsx-soak.sh` runs seeds in parallel on APFS clones. Failing seeds go to `Tests/fsx-regressions.txt`, which `Scripts/test-engine.sh` re-runs and CI will too — Step 06
- D-30: Ghosts (D-25) live in the root directory. fsx found that a ghost left in its parent made `rmdir` of an apparently empty directory fail with ENOTEMPTY. POSIX allows removing a directory whose only content is an open, unlinked file. Root placement also means crash leftovers sit in one known directory (Step 17 sweep) — Step 06
- D-31: The Windows oracle is `Scripts/chkdsk-vm.sh`. It wraps an image as a fixed VHD (`Tests/oracle/mkvhd.c`: an MBR with an NTFS partition at LBA 2048, hidden sectors patched to 2048, VHD footer), attaches it read-only with `Mount-DiskImage`, runs `chkdsk X:` with no `/f`, and stores the report with the image SHA-256 in `Tests/oracle/`. It is automated over SSH (`WINDOWS_SSH=user@host`, a Windows 11 Arm VM in UTM or Parallels with OpenSSH Server); otherwise it prints the manual steps (`docs/testing.md`) — Step 06
- D-32: Fuzzing: `Tests/Fuzz/fuzz_probe.c` and `fuzz_open_ls.c` are libFuzzer targets built with Homebrew LLVM (Apple clang ships no libFuzzer runtime), with ASan and UBSan, against a sanitized libntfs-3g (`Scripts/build-ntfs3g.sh --fuzz` → `build/ntfs3g-fuzz`). Inputs use a "sector list" format (image size, then sector records), so mutations hit real metadata. Crash inputs are kept in `Tests/Fuzz/crashes/` and replayed on every run — Step 07
- D-33: The fuzz build disables UBSan `alignment` (libntfs-3g reads packed on-disk structs; fine on arm64) and `shift-base` (libntfs-3g sign-extends with `(s8)x << 8` throughout `runlist.c`; clang compiles it as two's-complement). Every other UBSan check aborts. Patch 0002 (`bootsect.c`, huge `number_of_sectors` overflowing the byte offset) is kept as hardening, because there the overflow produced a garbage seek — Step 07
- D-34: Golden images are made without Windows for now (`Tests/Images/make-golden.sh`): ntfs-3g-made content and dirty/hiberfil images, plus synthetic `$LogFile` restart pages (v1.1 clean, v1.1 unclean, v2.0 Fast Startup) written by `mkfixture logfile`. Expectations come from construction, not engine output. Windows-made images are still wanted (`Tests/Images/README.md`) — Step 07
- D-35: CI is `.github/workflows/engine.yml` on GitHub's `xcode-27` image (macOS 27 + Xcode 27, a preview label). Steps: build ntfs-3g (cached on VERSION, patches and the build script), build all Xcode targets, Swift packages, `test-engine.sh` with `UNLATCH_SKIP_BIG=1` (the 4 GiB checks stay local), golden images, fsx regressions plus 100 random seeds, and 60 s per fuzzer. FSKit is not tested in CI — Step 07
- D-36: FSKit module shape, from the macOS 27.2 SDK headers, Xcode's File System Extension template, and Apple's own exFAT module `Info.plist`:
  - **Entry point:** `@main UnlatchFSExtension: UnaryFileSystemExtension`, which returns `UnlatchFileSystem` (an `FSUnaryFileSystem` adopting `FSUnaryFileSystemOperations` and `FSManageableResourceMaintenanceOperations`).
  - **Volume:** `NTFSVolume`, an `FSVolume` adopting `FSVolume.Handler` (plus `ReadWriteHandler` for reads). Handler protocols only (review A5).
  - **`Info.plist`:** `FSShortName` `unlatch`, block resources only, `FSVolumeAlwaysIgnoreOwnership`, personality "NTFS (Unlatch)". `FSMediaTypes` covers `Windows_NTFS`, GPT `EBD0A0A2-…` and `Partitionless` (probe order 2000/2000/4000, as exFAT uses).
  - **Probe results:** CLEAN → `.usable`; DIRTY, HIBERNATED, UNCLEAN_LOG → `.usableButLimited`; CORRUPT → `.recognized`; NOT_NTFS → `.notRecognized`. The container ID is a UUID built from "UNLTNTFS" plus the 64-bit serial.
  - **Load:** probe again, then open read-only unless CLEAN, writable and not `--rdonly`/`-r`. Corrupt or not-NTFS → container `.blocked`. `startCheck` re-probes and fails only for CORRUPT or NOT_NTFS; `startFormat` → ENOTSUP.
  - **Items:** one `NTFSItem` per NTFS reference, kept until `reclaimItem` (which calls `ue_release`). File IDs: root → 2, others → the full reference. uid/gid are 99. Hidden → `UF_HIDDEN`, read-only file → `UF_IMMUTABLE`, compressed → `UF_COMPRESSED`. `inhibitKernelOffloadedIO` stays on until Step 15.
  - **`enumerateDirectory`:** without attributes, packs synthetic `.` and `..` as cookies 1 and 2 (the engine's own positions for them), then calls `ue_readdir` from 2. The verifier is never 0.
  - **Queues:** each volume has a serial queue; probe and open share a global one.
  - **Block I/O:** synchronous `FSBlockDeviceResource.read/write` only, with unaligned head and tail blocks bounced through one preallocated scratch block — Step 08
- D-37: Signing lives in `Config/Base.xcconfig`: ad-hoc, no team, entitlement paths empty. It includes an optional, git-ignored `Config/Local.xcconfig` (template: `Local.xcconfig.example`) that sets `DEVELOPMENT_TEAM`, Automatic signing and the two entitlement paths through `UNLATCH_APP_ENTITLEMENTS` and `UNLATCH_EXT_ENTITLEMENTS`. CI and machines without a team still build; signed builds carry the entitlements (supersedes the "unreferenced entitlements" half of D-06) — Step 08
- D-38: A free Personal Team cannot sign the extension. Xcode refuses the provisioning profile: "Personal development teams … do not support the FSKit Module capability" (Xcode 27.2, 2026-11-01). Mounting through FSKit, and so Steps 08 (mount checks) to 11 and the M0 gate, needs a paid Apple Developer Program membership. CI stays ad-hoc (D-37) — Step 08
- D-39: Mount through macFUSE's FSKit backend instead of our own FSKit module. A free Personal Team cannot sign an FSKit module (D-38) and the owner does not want a paid membership; macFUSE ships its own signed FSKit extension, needs no kernel extension with `-o backend=fskit`, and libntfs-3g is already built for FUSE. Costs: users must install macFUSE (closed source, free; never bundled), and the FSKit backend lacks some FUSE operations (locks, xattrs, readdirplus). The engine (Steps 03–07) is unchanged; `Extension/` stays, dormant. Plan Steps 08–11 rewritten, 12–20 re-scoped at each step — Step 08
- D-40: `unlatch-fuse` (`Fuse/`) uses libfuse3's low-level API with macFUSE's Darwin extensions (`fuse_darwin_attr`: flags and birth time). FUSE node IDs are engine references, the root is `FUSE_ROOT_ID`; the daemon counts lookups per node and calls `ue_release` when `forget` brings the count to zero. The session loop is single-threaded, which serializes engine calls. Built against `$(MACFUSE_PREFIX)` (default `/usr/local`) — Step 08
- D-41: Status records live in `~/Library/Application Support/Unlatch/status/<serial>.json`, not the App Group container: the daemon is not sandboxed and has no App Group entitlement, and nothing is signed with a team. Same JSON as `UnlatchCore.VolumeStatus` — Step 08
- D-42: macFUSE's FSKit backend mounts only under `/Volumes` (elsewhere: "Failed to create mount point"), needs no sudo, and ignores `ro` (the volume is read-write to FSKit; `unlatch-fuse` refuses every write itself). Its read path is not usable yet: on macOS 27 with macFUSE 5.4.0 and 5.5.0, uncached reads of 256 KiB or more fail with `EIO`, reproduced without Unlatch in `Tests/Fuse/macfuse-repro/`. Step 08's "Done when" waits for a macFUSE fix or an owner choice of another transport — Step 08
- D-43: `unlatch-fuse` defaults to macFUSE's kernel-extension backend (`--backend kext`); FSKit stays available with `--backend fskit` and becomes the default again once D-42 is fixed upstream. The kext backend passes every Step 08 check (large and sparse reads included), honours `ro`, and mounts anywhere, but needs macFUSE's kext allowed once (Apple Silicon: Reduced Security in Recovery, then approval in System Settings). This Mac already has it loaded. Step 11 benchmarks both backends — Step 08
- D-44: The engine seam gains `ue_set_log(fn, ctx)` (`Engine/src/log.c`): libntfs-3g's errors, warnings and info go to a host callback, keeping ntfs-3g headers inside `Engine/src`. `unlatch-fuse` sends them to OSLog category `engine` and its own messages to `mount` (`Fuse/log.c`). Additive, so `UE_ABI_VERSION` stays 1 — Step 09
- D-45: Daemon details from Step 09. It backgrounds by re-running itself with `posix_spawn` (`-f --ready-fd N`) instead of `fork`, because OSLog and CoreFoundation are unsafe after fork without exec; the parent returns only once the mount point really is a macFUSE mount. Files report `st_blksize` 1 MiB, which makes macFUSE's kext issue 1 MiB reads instead of 16 KiB (cold reads 0.4–0.9 → 3.6–4.0 GB/s from a cached image). `/dev/diskN` is opened as `/dev/rdiskN` (1.2 → 1.6 GB/s). uid/gid are the mounting user's; the root never carries `UF_HIDDEN` (Windows marks it hidden+system, which would hide the volume) — Step 09
- D-46: Read-write in `unlatch-fuse`: only when the probe says CLEAN, the device opens writable and `-r` was not given; otherwise read-only, logged with the reason. After a failed device write, or ENXIO/ENODEV on read, the engine fails every later call with EIO and writes nothing more (`ue_has_failed`). chown/chgrp succeed and change nothing (NTFS has no owners here); of the BSD flags only `UF_HIDDEN` maps (to `FILE_ATTR_HIDDEN`), others are ignored; mode maps to the DOS read-only bit (files only). `flush` (close) is a no-op because engine writes go straight to the device (no longer true since D-62: they reach the disk on the 1 s write-back timer, fsync or unmount, and close still needs nothing); `fsync`/`fsyncdir` flush the device cache (`F_FULLFSYNC`). Symlinks and hard links return ENOTSUP until Step 16. Entry and attribute cache: 1 s read-write, 60 s read-only — Step 10
- D-47: The daemon asks macFUSE for `FUSE_DARWIN_CAP_CASE_INSENSITIVE` (without it a case-only rename is a silent no-op) and `FUSE_DARWIN_CAP_RENAME_EXT`. Until xattrs are native, macOS stores every xattr, including the `com.apple.provenance` it adds to every new file, as `._` AppleDouble files. That breaks `git fsck` (`._main` in `.git/refs`), and since libntfs-3g lists directories in index-block order, `rm -r` can delete `x` (and with it `._x`) before reaching `._x`, then report ENOENT. `-o noappledouble` is no fix: xattr writes then fail with EPERM and old `._` files become undeletable. So Step 16's xattr part comes next, before Step 11 (the plan allows Step 16 any time after Step 10). Resolved by D-48 — Step 10
- D-48: Xattrs are named `$DATA` streams with the same name (`Engine/src/xattr.c`), as ntfs-3g does on macOS: Windows sees `file:name` as an alternate data stream, Linux ntfs-3g (`streams_interface=xattr`) shows `user.name`. `:` cannot appear in a stream name, so it is stored as U+F03A, the private-use substitute Windows Services for Mac and WSL use (`com.apple.metadata:_kMDItemUserTags` → stream `com.apple.metadata\uF03A_kMDItemUserTags`). `com.apple.FinderInfo` and `com.apple.ResourceFork` are ordinary streams; the resource fork takes positioned writes. Values are capped at 64 MiB (`UE_XATTR_MAX`, E2BIG). With xattrs native, macOS writes no `._` files, which resolves D-47 — Step 16
- D-49: Links. Created symlinks are WSL symlinks (`IO_REPARSE_TAG_LX_SYMLINK`, UTF-8 target verbatim; libntfs-3g's `special_files = WSL`), readable by WSL on Windows and by Linux ntfs-3g. Readlink understands native symlinks, junctions, WSL and Interix links; a junction is a directory but shows as a link, as with ntfs-3g. Absolute Windows targets on this volume are shown under the mount point, targets on other drives as `<mount>/.NTFS-3G/D:/...` (unresolvable, ntfs-3g's convention). Hard links use `ntfs_link`; directories cannot be linked (EPERM). A symlink's `st_size` is 0 — Step 16
- D-50: The DOS read-only bit is shown only as a missing `w` in the mode, never as `uchg`. Showing it as immutable made 0444 files undeletable, and git writes its pack files 0444. `chflags uchg` on a file still sets read-only, and `chmod u+w` clears it — Step 16
- D-51: `unlatch-fuse` opens `/dev/diskN` as given (the buffered node), not `/dev/rdiskN`. On an attached disk, 2,000 small files took 0.69 s buffered against 5.3 s raw, and metadata 0.68 s against 8.4 s; sequential writes are 2.4× slower buffered. Mixing the two nodes would leave stale cached blocks. `/dev/rdiskN` given explicitly is used raw. Step 15 should recover large-I/O speed with an engine-side cache over the raw node — Step 11
- D-52: M0 gate thresholds, judged on the same backing as stock ntfs-3g (the image file): sequential read ≥ 60% of APFS, sequential write ≥ 40%, and no slower than stock ntfs-3g. Met (339%, 57%, faster on all six tests), so **GO** (`docs/M0-gate.md`), with the owner's agreement that NTFS may be slower than native file systems. The disk path's gap (13% read, 16% write, D-51) is Step 15's job. Stock ntfs-3g needs root for block devices, so a like-for-like disk comparison is not possible unprivileged — Step 11
- D-53: Real disks' device nodes are `root:operator` 0640, so until Step 12's privileged helper, `unlatch-fuse` mounts them with `sudo`. Under sudo, files belong to `SUDO_UID`/`SUDO_GID`, and `allow_other` is added so the user sees the mount. Attached images belong to the user and need no sudo — Step 17 (found on the owner's disk)
- D-54: `ue_readdir` skips an entry whose MFT record cannot be read (for example all zeros), logging a warning, instead of failing the whole listing. ntfs-3g behaves the same way. On the owner's real disk one such entry (record 352642) made a directory list as empty. A device failure or ENOMEM still ends the listing. - D-93: **Check Disk: Unlatch checks a volume itself and repairs only bitmap bits** (owner's request; refines D-90, D-92). `ue_check` (`Engine/src/check.c`) opens the volume read-only and reads the MFT raw: every record in use must be marked in `$MFT`'s bitmap, every cluster a runlist uses must be in `$Bitmap` and claimed once and inside the volume, every record in use must read back (fixups) and pass `ntfs_mft_record_check`, every directory must list (`ntfs_readdir`, which reads every index block its `$I30` bitmap marks) and its entries must point at base records in use with matching sequence numbers, and every named record must be listed somewhere (orphans). A volume libntfs-3g refuses because `$MFTMirr` differs from `$MFT` is reported as `mft_mirror` (the only check possible then). `UE_CHECK_REPAIR` runs only when every problem is a missing bitmap bit: the volume is then opened read-write, checked again, the bits set (at worst space is lost, nothing is overwritten), checked once more, and the dirty mark cleared only if that last check finds nothing; a dirty volume with nothing found is only unmarked. Anything else is reported and nothing is written: a partial repair would make chkdsk's job harder and a wrong one loses files. Hibernated and unclean-journal volumes are never repaired (EPERM). Records and clusters marked used but used by nothing are counted (`lost`), not problems. Hosts: `unlatch-engine check`, `unlatch-fuse --check [--repair] --fd N` (JSON on stdout; takes the volume's D-81 lock, shared to check and exclusive to repair, so it never runs beside a read-write mount), `MountService.check` (unmounts whoever has the volume, opens the device as a mount does, remounts), `unlatch check` (exit 5 when problems are left) and the app's "Check Disk…" for dirty and corrupt volumes. `ntfsfix -n` checks only the boot sector, `$MFTMirr` and the volume flags, so it agrees with none of the planted damage (all seven fixtures pass it) — follow-up
- D-94: **A disk that needs checking is asked about at mount time, and both ways to read-write clear the mark** (owner's request; supersedes D-90, and D-92's menu item). When a mount the app makes (automatic or from the menu) comes up read-only because the volume is DIRTY, one dialog offers Keep Read-Only (default), Check Disk and Enable Read-Write (`MountService.check(repair: true)`, D-93: the mark is cleared and the volume remounted read-write only when nothing is left; otherwise it stays read-only with the report), and Enable Read-Write Without Checking (`mount(markChecked: true)`, D-92: cleared at the clean close). Asked once per plug-in for automatic mounts; a mount the user asks for, or the disk's "Enable Read-Write…" menu item, asks again. Check Disk… stays in the menu (check without repair, and for CORRUPT). Writing while keeping the mark (D-90) is gone: `unlatch-fuse --dirty-rw`, `MountService.mount(dirtyReadWrite:)`, `unlatch mount --dirty-rw` and the app's "Mount Read-Write Anyway…"/"Mark as Checked…" are removed; `--mark-checked` keeps its name (CLI and daemon) since released scripts use it. Only DIRTY: hibernated, unclean-journal and corrupt volumes get no prompt — owner's request
- D-95: **The dirty mark is on the disk only while the volume is being changed, and a disk that comes back marked is checked before anyone is asked** (owner's request: a disk pulled out while idle should not need checking; refines D-86 and D-94). The engine no longer writes the mark at `ue_open`: `ue_mark_busy` (every call that changes the volume: write, create, remove, rename, setattr with a mask, xattr set/remove, symlink, link, ghost deletes, the crash sweep, Check Disk's repair) writes and flushes it before the change, and `ue_settle(e, idle_ms)`, once no change has come for idle_ms, does what a clean close does (closes and reopens `$Secure`, syncs the system inodes, writes the cache back, flushes) and clears it. `unlatch-fuse`'s flusher calls it with 2 s. A volume dirty at open keeps its mark unless `UE_OPEN_CLEAR_DIRTY`, which now clears it at the first settle. A device write while the mark is off counts in `ue_stats_t.unmarked_writes` (the write tests and fsx expect 0; fsx's sync op also settles and probes the image). Cost: one record write and flush per idle-to-busy change, one settle per idle period. In the app, a mount that comes up read-only because the volume is DIRTY first runs Check Disk (read-only); nothing found: the safe repair clears the mark and it mounts read-write without a question; problems found or the check failed: D-94's dialog, with what was found (Repair and Enable Read-Write only when Unlatch can repair it, else Copy Report). The CLI does not check by itself (it prints the hints) — owner's request
- D-96: **Check Disk also removes folder entries that lead to no file** (refines D-93). An entry is removed only when its record is not in use (within the MFT), is in use with another sequence number, or is in use but has no `$FILE_NAME` naming that folder; never one past the end of the MFT or at an extension record (`$MFT` may have lost an extent), and the record is never touched. The DOS half of a DOS+Win32 pair goes too. The repair still runs only when every problem is repairable, so an unreadable index or an orphan (a reused record's file listed nowhere else) blocks it; the entry is looked up again by its exact name in the read-write pass and removed only while it still points at the same reference (`ntfs_index_lookup` + `ntfs_index_rm`, as `ntfs_index_remove`). Bitmaps are repaired first, since removing an entry can allocate an index block. New kind `entry_wrong_parent`; `entries_removed` / `entriesRemoved` in the result. — chkdsk removes the same entries, and Mac-only users have no chkdsk; the commonest pull damage on a real stick is exactly this — follow-up
- D-97: **Write-back is ordered so that what is pointed to reaches the disk before what points at it** (refines D-62; a real SanDisk pull on 2026-11-03 left an entry pointing at an unwritten record). `bc_writeback` sorts dirty pages into phases and keeps D-62's sorted, merged transfers within each: (1) file data (pages dirtied cold) and the `$Bitmap`/`$MFT` bitmap pages, then `$MFT`'s first page with `$MFTMirr` right after it; (2) new index blocks (pages whose clean copy was not `INDX`); (3) records created since the last write-back (`ue_create`/symlink hint, `bc_hint_new`), highest first so a new folder lands after the files in it; device flush; (4) other index blocks and everything else; flush; (5) other MFT records (index roots, `$I30` bitmaps, runlists, freed records). Until the first flush everything new is unreachable, so a cut leaves orphans and lost space, not broken entries; a delete removes the entry (4) before freeing the record (5), but its bitmap bits clear in (1), which Check Disk repairs. Ranges come from the mapped runlists of `lcnbmp_na`, `mftbmp_na`, `mft_na`, `mftmirr_na` (`order_ranges` in `device.c`, no I/O), set while the volume is open read-write and cleared before libntfs-3g tears it down. Cost: two flushes per write-back (`ue_cache_stats_t.order_flushes`), measured in `docs/PROGRESS.md`. Left: a cut between `$MFT`'s first page and `$MFTMirr` still leaves them apart (one transfer boundary per write-back that changes records 0–3) — follow-up
- D-98: **Check Disk rewrites a $MFTMirr that a cut left behind $MFT** (refines D-93; owner's request: such a disk should not need Windows). When libntfs-3g refuses a volume and `$MFTMirr` differs from `$MFT` within the system records it compares, `ue_check` reads `$MFT`'s first n records raw at `mft_lcn` (n = `vol->mftmirr_size`: 4, or a cluster's worth) and, with `UE_CHECK_REPAIR`, writes them unchanged (fixups as on the disk, not re-protected) over `$MFTMirr` at `mftmirr_lcn` through `io->pwrite`, then flushes, probes again and runs the normal check and repair in the same call, so one `check --repair` handles a disk with both kinds of damage (`mirror_repaired`; the result's state stays `corrupt`, and the mirror counts as one problem found and repaired). Only when every one of the n `$MFT` records has the FILE magic and passes `ntfs_mst_post_read_fixup_warn`, records 0–3 are in use, every record in use passes `ntfs_mft_record_check`, and records 0 and 1 place `$MFT` and `$MFTMirr` (first run of their `$DATA`) where the boot sector does; anything else is reported (`mft_mirror`, not repairable, with the reason) and nothing is written. $MFT is the newer copy since D-97 writes its first page before `$MFTMirr`. The other way round (the mirror over a torn `$MFT` record) is not done: the older record 0 can describe a shorter `$MFT` or lose a change to `$Volume`, so that stays chkdsk's. The copy happens before the hibernation/journal check, which needs the volume open; the mirror then matches what Windows itself would write. As ntfsfix's `fix_mftmirr` and chkdsk do — Mac-only users have no chkdsk, and 24 of 255 cuts in `test_cut_order` left this — check disk
- D-99: **Check Disk puts files no folder lists back** (refines D-93, D-96). An orphan (a base record in use with a `$FILE_NAME`, beyond the system records, that no folder lists) is repairable when its record passed pass 1 whole: fixups, `ntfs_mft_record_check`, a readable runlist inside the volume, no shared clusters (`flawed`). The repair, after the bitmaps and D-96's entry removals (a removed entry can free a name), opens the record again and acts only while it is still an orphan (in use, same sequence number, a base record, and none of its folders lists it). If every `$FILE_NAME`'s parent is an in-use, undamaged folder with a matching sequence number that is listed in a folder up to the root, and no file there has the name (`ntfs_inode_lookup_by_name`, case-insensitive as Windows looks up), the record's own `$FILE_NAME`s go back as index entries (`ntfs_index_add_filename`, a DOS+Win32 pair as both). Otherwise its names are removed and one POSIX name, `file<rec>` or `dir<rec>` (`.1`, `.2`… if taken), is linked in `/found.000` (`ntfs_link`; made with `ue_create` when missing; `found.001`… when the name is a file), as chkdsk's `found.NNN`. Orphans going back in place are relinked in passes, so a folder put back makes its orphaned children reachable; the rest go to found. The data is never touched. Counters `orphans_relinked`, `orphans_found`. Check Disk also now follows each folder index's child pointers, which `ntfs_readdir` does not: a node pointing at an index block outside `$INDEX_ALLOCATION` or not marked in its bitmap is `index_unreadable` (a cut can leave it; every lookup past it fails EIO). — the orphans a cut leaves since D-97 are whole new records; sending such disks to Windows was the last common case — check disk
- D-100: **Write-back order, refined: changed records before index blocks, index nodes before leaves, freed records last, and $MFT pages written record by record** (refines D-97; a wider cut-off sweep found a folder's index unreadable after a cut). `bc_writeback` now writes: (1) data and bitmaps, `$MFT`'s first page and `$MFTMirr`; (2) new index blocks; (3) new extension records, then other metadata (pages that are neither records nor index blocks: non-resident attribute lists, `$SECURITY_DESCRIPTOR`s, `$I30` bitmaps, stream values; `$Secure`'s record and its `$SII`/`$SDH` leaf blocks, told by 4- or 8-byte keys), then new base records, highest first; flush; (4) changed records, highest first; flush; (5) existing index blocks, nodes (`LARGE_INDEX`) before leaves; flush; (6) freed records. A record is new or freed by its header (`FILE`, in use, sequence number) against the copy the disk held when its page was last clean (`note_slots`), so extension records and records that libntfs-3g allocates itself count too, not only the `ue_create` hint; a page written whole is taken as holding no records. Pages of `$MFT` are cut into record-sized pieces when their records fall in different phases (adjacent pieces of one phase still join). Fixed: a new record pointing at an unwritten attribute list (unreadable folder) or security descriptor (chkdsk "replacing missing or invalid security descriptor"), a node block pointing at a VCN its folder's record did not map yet (unreadable folder), and a delete freeing a record before its entry in the same MFT page. Not fixable by order (the folder's record must land before nodes that use its runlist, and a rename's add and remove are in different blocks): a new block that readdir lists but lookup does not reach, a split's old tail listed twice, and an entry under a name its record no longer has; Check Disk needs to find these (carry-over). Measured in `docs/PROGRESS.md` — follow-up
- D-101: **The chkdsk oracle for Check Disk runs read-only `chkdsk X:` (no `/f`, no `/scan`) on each image after `unlatch-engine check --repair`** (`Scripts/chkdsk-vm.sh --scan <img>...`, reports and `summary.tsv` in `build/chkdsk/`). `/scan` needs a shadow copy, which a VHD attached read-only cannot give (exit 11, "Run an offline scan"), and attaching it read-write would let Windows change the volume before the check; without `/f`, chkdsk falls back to the same read-only scan, as D-55's fsx checks did. Clean is exit 0 and "found no problems". Cut images come from `test_check_cut_copy` and `test_cut_order` through `UNLATCH_CUT_SAVE=<dir>` (every `UNLATCH_CUT_SAVE_EVERY`-th cut, default 4) — the owner wants to tell users Check Disk replaces chkdsk after a pull, and Windows' own checker is the independent proof — follow-up
- D-102: **Check Disk frees space marked used by nothing, and replaces damaged security descriptors** (refines D-93, which left lost bits alone; Windows chkdsk on D-101's images reported "free space marked as allocated" in 60 cuts Check Disk called clean, and "Replacing missing or invalid security descriptor" in 7). (1) `$MFT`'s bitmap is read whole, so bits past `$MFT`'s last record (an extension a cut never finished) count as `lost_records`. With `UE_CHECK_REPAIR`, once the volume checks clean (after every other repair and the check that follows them, in the same read-write open), `clear_lost` clears the `$MFT` bitmap bits of records not in use and the `$Bitmap` bits of clusters no runlist uses, then the volume is checked once more; anything still lost counts as left, so the dirty mark stays. A repair now runs for lost bits alone (`records_freed`, `clusters_freed`; `unlatch-engine check` exits 1). Safe only then: every record in use was read whole and every runlist decoded, so nothing in use is freed. (2) New kind `bad_security`: a `$SECURITY_DESCRIPTOR` attribute that `ntfs_valid_descr` rejects (resident in pass 1, non-resident read after the directories) is repairable: the attribute is removed (`ntfs_attr_rm`, its clusters freed) and, when `$STANDARD_INFORMATION` has no security_id, `ntfs_sd_add_everyone` adds the descriptor every file Unlatch creates has (`security_replaced`). A security_id that `$Secure`'s `$SII` does not hold is reported, not repaired: Unlatch's writes never produce one, and choosing another id would change who may open the file. Cause of the 7 cuts: a folder whose record grew moved its `$SECURITY_DESCRIPTOR` out to a cluster, and the cut landed the record before that cluster (all zeros); write order, closed by D-100's "other metadata before records" phase. — check disk
