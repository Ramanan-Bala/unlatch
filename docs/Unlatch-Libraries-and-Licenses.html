01The short version

If you read only one section, read this.

  1. There is only one mature, open, read-write NTFS library you can run in-process: libntfs-3g. It is GPL v2 or later, not LGPL. Linking it into your extension makes the whole extension a GPL work. That is already your decision: GPL-3.0-or-later.
  2. “GPL-2.0 or later” combines cleanly with GPL-3.0. This is the one compatibility direction that unquestionably works. If it had been “GPL-2.0 only”, GPL-3.0 would have been incompatible and you would be forced to GPL-2.0.
  3. GPL forbids the Mac App Store, not the DMG. Developer ID signing, notarization and Sparkle updates are all fine. Charging money is fine. Hiding the source is not.
  4. The FUSE layer is optional. ntfs-3g is built from a library plus a FUSE driver. Unlatch uses the library only, so macFUSE and FUSE-T never ship — avoiding their own restrictive terms (macFUSE forbids bundling in commercial software; FUSE-T requires a paid license for commercial use).
  5. Everything else in the stack is permissive (Apache-2.0, MIT, BSD). They only need attribution, not source disclosure. Only the engine drives the GPL decision.
  6. The library is alive: latest release 2026.9.28, a few weeks before this page was written. It is mature rather than modern: single-threaded, no real fsck, and its allocation policy is not tuned for 4K random writes.
What this means for you

Say “yes, open source, GPL-3.0-or-later, source on GitHub, free DMG” and nothing else on this page changes. Say “no, I may want this closed or paid-proprietary someday” and the whole engine plan changes: there is no credible closed-source replacement, so you would be starting a multi-year engine project or licensing one commercially.

03License primer, in the order it matters to you

GPL-2.0-only vs GPL-2.0-or-later vs GPL-3.0

A license header that says “version 2, or (at your option) any later version” lets you use the code under GPLv2 or any later GPL, including v3. That is why libntfs-3g's volume.c header says “either version 2 of the License, or (at your option) any later version”, and why the project ships a GPLv2 COPYING file while still being usable in a GPLv3 work.

If the dependency were…Combining with GPL-3.0 codeMeaning for Unlatch
GPL-2.0-or-later (what it is)AllowedWhole work is GPL-3.0-or-later. Done.
GPL-2.0-onlyIncompatibleYou would have to license Unlatch GPL-2.0-only.
GPL-3.0-onlyAllowedSame as now.
LGPL-2.1 / LGPL-3.0AllowedYou could keep Unlatch closed if you dynamically link and allow relinking. Not the case here.
Apache-2.0 / MIT / BSDAllowedNo source obligation, just notices.

What “linking” means, and why in-process matters

GPL obligations trigger when you form a combined work. A separate program that talks to another over a socket or command line can stay independent. Code compiled and linked into the same binary — or loaded as a plugin into the same process — is the classic combined work.

  • Unlatch links libntfs-3g statically into the extension. Combined work. The extension, and the app that embeds it, are GPL.
  • The FUSE design was no different. ntfs-3g running as a separate process would have been a boundary, but you would then be GPL-ing the driver too, and paying the FUSE performance cost for the privilege.
  • Your engine seam does not change the license. It changes who you can swap in later. As long as libntfs-3g is in the product, the product is GPL.

What GPL-3.0 lets you do to users' machines

Fine

  • Charge money for the DMG, or ask for donations.
  • Sign and notarize with your Developer ID.
  • Ship updates through Sparkle, signed with your key.
  • Require users to enable the extension in System Settings.
  • Use Apple's proprietary frameworks, as long as you don't redistribute them.

Not fine

  • Distributing a binary without the corresponding source.
  • Adding terms that forbid reverse engineering or redistribution (every App Store and most EULAs).
  • DRM or a licence check that stops a modified build from running.
  • Relicensing the combined work as “GPL plus commercial” unless you own every line.
Why the App Store is out either way

Two independent blockers: (1) the Mac App Store terms add restrictions the GPL forbids; (2) FSKit filesystem extensions are distributed outside the store and need a Developer ID + user approval. This was never a real option, so losing it costs you nothing.

04libntfs-3g in depth

What it is

ntfs-3g began as the Linux-NTFS project's userspace driver and is now maintained by Tuxera. The source tree produces two things:

  • libntfs-3g — the engine: boot sector parsing, $MFT, runlists, attributes, directory indexes, the journal, compression, encryption. This is what Unlatch links.
  • ntfs-3g the driver — a thin FUSE front end over the library. This is what you are not using, and what the old design used.

Both are GPLv2-or-later. The library is not independently LGPL, despite what older blog posts and the guide said.

Why it is the only realistic engine

It actually writes

Full file and directory create, write, rename, delete, truncate, compression, sparse files, and journal handling. Decades of bug reports behind it.

It accepts foreign block I/O

ntfs_device_operations lets you supply read/write callbacks, so it never opens /dev/disk itself. That is the property that makes the FSKit design possible at all.

It is maintained

Release 2026.9.28 landed five weeks before this page. Slower than a startup, but not abandoned.

Commercial licensing exists

Tuxera sells commercial licences for the NTFS-3G technology. If you ever want a closed-source Unlatch, that is the conversation — expect per-product or per-seat terms, an NDA, and no public pricing. Treat it as a fallback, not a plan.

The license trap in the table

Both fully capable open engines are GPL. The permissive options cannot write. So “permissive license + full read/write” does not exist today at any price except a commercial contract. That single fact decides your project license.

06Mounting approaches compared

How the filesystem reaches macOS decides performance, install friction and your own license exposure. This is the part the original guide got mostly right.

Why this matters for licensing

By choosing FSKit you avoid redistributing macFUSE or FUSE-T. That removes two separate commercial-use restrictions and one closed-source kernel extension from your product. Your only copyleft obligation is the one you already accepted.

07Your GPL-3.0 obligations, concretely

A checklist you can hand to a lawyer, or just follow. Every item is cheap; skipping one is what gets projects in trouble.

#ObligationHow Unlatch satisfies it
1License your own code under GPL-3.0-or-laterLICENSE at repo root; short SPDX headers in source files
2Provide complete corresponding source for each binary you distributePublic repo, one tag per release, and the exact project.yml, patches and scripts needed to rebuild
3Include the full license texts of everything you shipIn-app “Open Source Licences” screen plus a NOTICES file in the DMG: GPL-3.0, ntfs-3g's GPL-2.0, Apache-2.0 + NOTICE, MIT
4Do not add restrictions on topNo EULA terms that forbid reverse engineering or redistribution; the DMG can be copied and shared freely
5Do not prevent modified versions from runningNo licence check or DRM. Notarization does not prevent this: anyone can build and run their own signed copy
6Keep copyright notices intactVendored source retains its headers; patches documented
7State changes if you modify the enginePatches live in Engine/vendor/patches/ with a note in README
8Offer source to anyone who receives the binary“Source” link in the app's About screen pointing at the matching tag, plus the repo URL in the DMG
Two things people get wrong

“I'll publish the source later.” The obligation starts when the first binary is distributed, not when you feel ready.

“The engine is a separate module, so only it is GPL.” Statically linked into one extension means one combined work. The seam keeps the code clean and replaceable; it does not partition the license.

Do you need a CLA?

If you might ever dual-license (GPL for the community, paid licence for closed integrators) or sell the project, you need the right to relicense every contribution. Choose now, because retrofitting is painful:

  • DCO (Developer Certificate of Origin) — lightweight, keeps the project purely GPL. Default choice for a community project.
  • CLA — contributors grant you relicensing rights. Slightly more friction, keeps the commercial option open.

09Decision sheet

Ten questions, each with a recommended answer. You can approve the whole column in one line.

1. Which NTFS engine?
Options: libntfs-3g · Linux ntfs3 port · Rust crate · commercial · write our own
libntfs-3g. Only mature read-write option that accepts foreign block I/O. Everything else is a multi-year detour.
2. What license does Unlatch ship under?
GPL-2.0-only · GPL-3.0-or-later · dual GPL + commercial
GPL-3.0-or-later. Compatible with the engine, gives you the stronger patent and anti-DRM terms.
3. Is the source public from the first release?
Public repo · source tarball per release only
Public repo, tag per release. A tarball alone is legal but looks evasive and makes contributions harder.
4. Distribution channel?
Free DMG · paid DMG · Mac App Store · Homebrew cask too
Developer ID DMG, free, plus a Homebrew cask. App Store is impossible; charge later if you want, the license allows it.
5. Will you ever sell a closed-source version?
No, never · maybe · yes
“No, not planned.” If “maybe”, adopt a CLA now and contact Tuxera for pricing before Step 03 — not after the code exists.
6. Contributor policy?
DCO · CLA · none
DCO. Unless answer 5 was “maybe” or “yes”, in which case CLA.
7. Can the app be commercial in other ways (support, sponsorship, paid builds)?
Yes · no
Yes. Selling binaries, support or sponsorship is allowed by GPL-3.0. Only the source obligation cannot be waived.
8. Do we bundle the ntfsprogs tools (format, repair)?
Never · format only · format + repair
Not in v1. If format ships later, ship the GPL notices and source link for it too — same obligation, no extra cost.
9. Do we ship or support macFUSE / FUSE-T at all?
No · as an optional fallback
No. Both add restrictive redistribution terms and install friction, and neither is needed with FSKit.
10. What goes in the notices bundle?
Minimal · complete
Complete: GPL-3.0 text, GPL-2.0 text (engine), Apache-2.0 + NOTICE (CLI), MIT (Sparkle), plus an “Open Source” screen linking the exact source tag.
If you accept all ten recommendations

Nothing further is needed before Step 01. The plan already assumes exactly this. If you change any of 1, 2, 5 or 6, tell me before the next session — those four ripple into the plan.

10Questions you'll be asked

Can I sell Unlatch?

Yes. GPL-3.0 lets you charge any price for binaries and support. What you cannot do is stop recipients from copying, modifying or redistributing the source. In practice: free build + paid support/company sponsorship is the common model.

Can I keep the source private and just ship the binary?

No. That is the one thing GPL forbids. And because the engine is GPL-linked, there is no “keep only my part closed” arrangement — the combined work is GPL.

What if I only dynamically link libntfs-3g?

Dynamic linking does not escape the GPL the way it can with the LGPL. Both static and dynamic linking of GPL code into your program produce a combined work. The LGPL is the license that permits closed linking under conditions; the engine is not LGPL.

Wasn't libntfs-3g LGPL? I read that somewhere.

Older summaries are wrong or refer to a different project. The checked source header in libntfs-3g/volume.c reads “GNU General Public License … either version 2 of the License, or (at your option) any later version”, and the tree ships a GPL-2.0 COPYING. Treat it as GPL-2.0-or-later.

Does notarization or Developer ID conflict with GPL?

No. Signing proves who built the binary; it does not restrict anyone from building and running a modified version. Apple's notarization service does not add license terms to your code.

Does Sparkle auto-update violate GPL?

No, as long as updates are optional and do not lock users to your build. Do not require a signature only you can produce in order to run the app.

Can I use macFUSE or FUSE-T in my build?

Technically yes for a free project. macFUSE's license forbids bundling its binaries in commercial software without permission; FUSE-T requires a paid licence for commercial use or bundling. Unlatch's FSKit design avoids both, which is one reason it exists.

What happens if Tuxera changes the license of a future release?

Pin the current tag and vendor the source. You can keep shipping the pinned version forever under its existing license. A newer release with worse terms is optional, not forced.

Can I switch to a permissive engine later?

Yes, but relicensing the project back to closed source requires owning every contribution. With a DCO-only policy you cannot; with a CLA you can. The seam makes the engine swap technical, not legal.

Is ntfs-3g safe enough for other people's data?

It is the same engine that has written NTFS volumes from Linux for nearly two decades, and it is more conservative than most alternatives (it refuses hibernated and unclean volumes rather than guessing). The plan adds a read-only-first safety rule, fsx randomized testing, and Windows chkdsk as the oracle. No NTFS writer is risk-free; NTFS has no metadata checksums.

What about Microsoft patents on NTFS?

ntfs-3g has been distributed worldwide since 2007 without a known action, and the relevant patents are old. GPLv3 also includes a patent grant from contributors. This is a residual risk to note, not a reason to avoid the design — and it applies equally to any NTFS implementation you could build.

Do I need a lawyer?

For a free GPL project using GPL libraries, the checklist in section 7 is the standard practice and is well understood. Get counsel if you plan to sell, if you accept outside investment, or if you want a commercial engine licence.

11Glossary

Copyleft

A license that requires derivative works to keep the same license. GPL is strong copyleft; LGPL is weak (library) copyleft.

Combined work

One program built from parts that call each other in-process. Linking GPL code into it makes the whole work GPL.

Corresponding source

Everything needed to build the exact binary: source, build scripts, patches, and license texts.

FSKit

Apple's framework for user-space filesystems, available from macOS 15.4 and substantially extended in macOS 27. Replaces kernel extensions and FUSE for this use case.

FUSE

Filesystem in User Space. The classic way to mount ntfs-3g on macOS; adds a process boundary and needs a runtime (macFUSE or FUSE-T).

Entitlement

An Apple-issued permission embedded in a code signature. The FSKit module and mount entitlements are granted through the Developer portal.
